Declare edits to a game bin to change some of its values without a copy of the whole file in your
mod. Each edit that you make in the bin editor becomes a key in the `game_data.yaml` of a layer,
and the build applies it to the game's copy of the bin.

<Where path={['Bin editor', 'Sandbox', 'Use game data declarations']} files="Game bin files" />

Prerequisites:

- A [project](/editor/projects/) with at least one layer
- The League installation path set in LTK Manager

## Declared bins

If no layer of your project ships a game bin, the bin opens as a declared bin. The bin editor shows
the game's copy with the declarations of every layer applied, in the order in which the build
applies them. The values in the bin editor are the values that the build writes.

For each edit, LTK Editor writes one key to the selected module in the `game_data.yaml` of the
selected layer. LTK Editor saves the file with each edit, so a declared bin has no unsaved changes.

See [Declaration manifests](/making-mods/game-data/) for the file format.

## Turn on declarations

1. Open a game bin from the **Game index** view, or follow a link to one.
2. In the tab header, select **Sandbox**, the button that shows the name of your project.
3. Turn on **Use game data declarations**.

   You can now edit the bin. The setting applies to the whole project.

When declarations are off, the bin still shows the declarations applied. A strip under the toolbar
shows **Declare edits**. Select it to turn the setting on.

## Choose the layer and module

In the **Sandbox** options, select the layer that receives your edits, and the module that receives
new keys. The layer defaults to the layer that you used last in the project, or to `base`.

A row shows a mark if a declaration of the selected layer sets it. Hover over the mark to see the
layer and the game's own value. If a declaration of another layer sets a row, the row shows the
applied value with no mark.

## Edit a row

Edit a value as in any bin. See [Editing bins](/editor/bin-editor/editing/). Each edit becomes one
declaration:

| Edit                             | Declaration                           |
| -------------------------------- | ------------------------------------- |
| Set a value                      | `path: value`                         |
| Add an entry to a map            | `+map: {key: value}`                  |
| Remove an entry of a map         | `-map: [key]`                         |
| Add an item at the end of a list | `+list: [value]`                      |
| Insert or move an item in a list | The whole list                        |
| Add a dependency                 | `links: [path]` in a `target` module  |
| Remove a dependency              | `-links: [path]` in a `target` module |

To remove a declaration, right-click its row and select **Reset to default**. The row then shows
the game's value again. Undo restores the `game_data.yaml` to its content before the edit. Redo
applies the edit again.

## Add and remove objects

| Action                      | Where                       |
| --------------------------- | --------------------------- |
| **Duplicate as new object** | An object row's menu        |
| **Object**                  | The toolbar's plus button   |
| **Remove object**           | An object row's menu        |
| **Restore object**          | A removed object row's menu |

Enter the name of the new object on the line under the objects of the file. The name starts with
`Mods/<mod>/`, followed by the name of the source object or the class. Press <kbd>Enter</kbd> to
declare the object. A removed object keeps its row, with the name struck through.

## Copy a row as a declaration

To copy a row of any bin as an `entries` module, right-click it and select **Copy as
declaration**. You can paste the module into a `game_data.yaml`. **Copy reference** copies a value
row as a `!ref` to the game's value. Both commands are available on a read-only bin.

In a declared bin, **Paste reference** sets a row to the copied reference, and **Merge reference**
adds it to a list or a map.

## Bins in a layer

When a layer of your project ships its own copy of a game bin, the bin opens as the file of that
layer. LTK Editor saves edits to the file and writes no key to a `game_data.yaml`. If a declaration
of any layer overrides a row in the build, the row shows the glyph of the declaring layer. Hover over it to see the value of
each layer and the value in the file. The build packs the value of the last layer.

## Limitations

- You cannot remove a property from a game bin. **Reset to default** writes the default value.
- You cannot declare a path that contains a field whose name is not in a hash table.
- You cannot declare a map key that the bin contains twice.
